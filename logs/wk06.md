## Predict Before You Delete

Three lines from `js/todo.js`, what I predicted would happen if I deleted them, and whether I was right:

1. `form.addEventListener('submit', function (e) { ... })` — **Predicted:** without this, clicking "Add" would do nothing at all since nothing is listening for the form to submit. **Result:** correct — the page just reloaded (the browser's default form behavior) and no task was added, since `e.preventDefault()` never ran either.
2. `list.innerHTML = filtered.map(function (todo) { ... }).join('');` inside `render()` — **Predicted:** the `<ul>` would stay empty forever, even after adding tasks, because this is the line that actually writes the task list back onto the page. **Result:** correct — tasks still got added to the `todos` array and saved to `localStorage`, but the list on screen never updated since nothing was rewriting `list.innerHTML`.
3. `saveTodos();` inside the submit handler — **Predicted:** tasks would still show up on screen right after adding them, but they'd disappear if I refreshed the page, since this is the line that writes to `localStorage`. **Result:** correct — new tasks appeared fine until I reloaded the page, at which point `loadTodos()` read the old (unsaved) list back from `localStorage` and the new tasks were gone.

## What gave me trouble

Pulling these specific lines out of `todo.js` and guessing what would break made me actually trace through the order the functions run in — before this I was treating `render()`, `saveTodos()`, and the event listeners as one blob that "just works" together.

## What gave me trouble

Most of what gave me trouble this week was reading JavaScript that AI generated for `todo.js` and not immediately understanding why it was written the way it was. I kept a running list of the specific lines I got stuck on instead of just moving past them:

### JS I don't understand (from the todo App)

- `(function () { ... })();` — the whole `todo.js` file is wrapped in this. I don't fully get why it's written as a function that immediately calls itself instead of just writing the code normally.
- `e.target.closest('li')` inside the list click handler — I understand `e.target` is whatever got clicked, but `closest()` is new to me and I'm not sure how it walks back up to find the parent `<li>`.
- `Number(li.dataset.id)` — I don't really understand what `dataset` is or why the id has to be converted with `Number()` instead of just comparing it directly.
- `todos.find(function (t) { return t.id === id; })` vs `todos.filter(...)` — both loop through the array, but I can't yet explain why one is used to find a single todo and the other to remove one.
- `try { ... } catch (e) { return []; }` in `loadTodos()` — I know this is "error handling" but I don't understand what would actually make `JSON.parse` fail here or why we need a fallback.
- The `escapeHtml()` function that creates a `<div>`, sets its `textContent`, then reads back `innerHTML` — this feels like a trick to clean up text, but I don't understand why that actually prevents problems.

This week made me realize that I can build something that works without actually understanding every line of it, which isn't great for actually learning. Going forward I want to stop and ask the AI to explain unfamiliar syntax like this instead of letting it pile up.
